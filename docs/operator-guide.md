# Operator Guide

## First Deployment

1. Define the subsistence household's service area and intake process.
2. Register each operator and gathering area (provenance basis for every proposal).
3. Run synthetic operating cases.
4. Enable human-reviewed sign-off for flagged livelihood concerns and
   above-threshold supply orders.
5. Measure operating outcomes and audit coverage.

## Minimum Production Controls

- provenance for all operating records (registered operator + area)
- harvest-report basis for every logged harvest record
- always-escalate path for flagged livelihood concerns
- human review for above-threshold supply orders
- audit export for all gated actions

## What This Actor Never Does

This actor and its operators must never configure, extend or fork it to:

- fire a weapon
- set or spring a trap
- make a fishing, hunting, trapping or gathering-execution decision
- make a kill or harvest-timing decision
- decide on area-use, season or catch/bag-limit questions

These are decisions that belong solely to the human household member (and,
for regulatory/customary questions, the relevant authority). This actor is
a logistics/record-keeping coordination robot only — any observation
suggesting a food-security, resource-depletion or safety concern is
surfaced solely via `:flag-livelihood-concern`, which always escalates
immediately to the human household member for review and action. The
robot never acts on it.

## Certification

Certified operators must prove that the governor gates every proposal,
that flagged concerns and above-threshold supply orders escalate to the
human household member, and that no fork has reintroduced an op or
rationale path resembling weapon-firing, trap-setting/springing,
fishing/hunting/gathering-execution, or a kill/harvest-timing decision.
